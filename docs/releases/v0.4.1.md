# Murmur 0.4.1 — consistent signing for updates

This update moves distribution builds from ad-hoc signing to **Developer ID Application signing**. **Apple accepted this build for notarization**, and the ticket is stapled to the app. It keeps the UI and folder features introduced in [0.4.0](https://github.com/krisekenes/murmur/releases/tag/v0.4.0).

## Why permissions needed to be granted again

The previous downloads were ad-hoc signed. Their macOS signing identity depended on a hash that changed with every build, so an existing Accessibility permission could refer to an older binary even when System Settings still showed Murmur enabled.

Developer ID signing gives releases a consistent identity through the app's bundle identifier and developer team. Future distribution updates will keep that identity. This addresses update recognition; notarization separately checks the application with Apple and improves the installation experience.

## Updating from 0.4.0 or earlier

1. Quit Murmur.
2. Download **Murmur-0.4.1-macOS-arm64.zip**, unzip it, and replace Murmur in Applications.
3. Open the updated app and grant any permissions macOS requests.

Moving from an ad-hoc build to a Developer ID build changes identity once more. If Accessibility still shows enabled but Murmur cannot use it, remove the old Murmur entry and add the updated app once. The goal is to eliminate this repeated cleanup on subsequent consistently signed updates; a two-version, end-to-end permission-retention test remains to be completed.

Use the distribution download for upgrade testing. Local Apple Development builds and ad-hoc CI previews have different signing identities and are not interchangeable with it.

## Release safeguards

- Distribution packaging requires Developer ID signing and a notarization profile before it builds.
- Local and CI archives require an explicit `--preview` option and use an `-unnotarized-preview` filename suffix.
- Seven configuration checks cover missing credentials, invalid signing types, preview mode, and conflicting options.
- Existing core and beta regression checks run during packaging.

## Validation

- 89 core tests, 12 beta state checks, and seven packaging-configuration checks passed.
- The Release build succeeded and its Developer ID signature verified.
- Apple notarization was accepted; the stapled ticket validated and Gatekeeper reported `Notarized Developer ID`.
- Permission retention across two distribution versions still needs a manual upgrade test. This release establishes the signed baseline for that test.

Requires Apple Silicon and macOS 14 or later. The `.sha256` asset provides the download checksum. Models download separately; conversations, folders, and notes continue using existing local storage.
